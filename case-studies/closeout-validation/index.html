Document AI vs CRM

Closeout Validation & PDF Reader

Prices, deposits and fees in the CRM were keyed in by hand, and mistakes often surfaced only after a deal closed. This tool reads the real settlement statements and checks every key field before closing.

AWS Lambda (PDF parser)Claude API (structured tool output)Google Apps ScriptSalesforce

How it flows

What I built

  • A Lambda function parses settlement statements and contracts. Statements it can't read go to Claude with a forced JSON tool schema, and each result is cached per file so a document is only paid for once.
  • Checks a dozen fields on every pre-close deal against the CRM: prices, deposits, admin, TC and wire fees, and interest.
  • Recomputes profit after holdback with Accounting's formulas, which differ for double closes and assignments, and checks fees against the fee schedule.
  • An extraction error log, designed for non-technical reviewers, captures every true miss and its root cause. Those labels become training data for the reader.

Outcome

  • 97–99% field accuracy against a hand-checked benchmark of a full year-to-date sample of deals.
  • Saves 35+ hours a week of manual document review.
  • Errors are caught before close instead of after.

Code excerpt

function cvClaudeRequest_(apiKey, pdfB64, docType) {
  var props = {};
  Object.keys(CV_HUD1_FIELDS).forEach(function (k) {
    props[k] = { type: [CV_HUD1_FIELDS[k][2], 'null'], description: CV_HUD1_FIELDS[k][1] };
  });
  var ip = {};
  Object.keys(CV_HUD1_LINE_ITEMS.fields).forEach(function (k) {
    ip[k] = { type: [CV_HUD1_LINE_ITEMS.fields[k][1], 'null'], description: CV_HUD1_LINE_ITEMS.fields[k][0] };
  });
  props.line_items = { type: 'array', description: CV_HUD1_LINE_ITEMS.description,
                       items: { type: 'object', properties: ip, required: Object.keys(ip) } };
  var tool = { name: 'record_fields', description: 'Record the fields extracted from the document.',
               input_schema: { type: 'object', properties: props, required: Object.keys(props) } };
  var prompt = 'This PDF is ' + (CV_HUD1_CONTEXT[docType] || 'a HUD-1 settlement statement. ') + CV_HUD1_RULE +
    '. Extract the requested fields exactly as the document states them. Use null for any field that is not in the document; do not guess. ' +
    'If a value appears more than once (e.g. changed by an addendum), use the controlling value and mention it in extraction_notes. ' +
    'Call the record_fields tool with your answer.';
  var headers = { 'x-api-key': apiKey, 'anthropic-version': '2023-06-01' };
  var ws = PropertiesService.getScriptProperties().getProperty('ANTHROPIC_WORKSPACE_ID');
  if (ws) headers['anthropic-workspace-id'] = ws;
  return {
    url: 'https://api.anthropic.com/v1/messages', method: 'post', contentType: 'application/json',
    headers: headers, muteHttpExceptions: true,
    payload: JSON.stringify({
      // Forced tool call: Haiku 5.5 thinks adaptively by default, but a forced tool_choice skips thinking — same
      // behavior as 4.5 and every reply is the record_fields call. max_tokens raised: 5.5 counts ~30% more tokens.
      model: CV.MODEL, max_tokens: 16000, tools: [tool], tool_choice: { type: 'tool', name: 'record_fields' },
      messages: [{ role: 'user', content: [
        { type: 'document', source: { type: 'base64', media_type: 'application/pdf', data: pdfB64 } },
        { type: 'text', text: prompt }
      ] }]
    })
  };

Building the Claude request: a PDF in, a schema-enforced JSON record out. Identifiers and internal names are anonymized.
